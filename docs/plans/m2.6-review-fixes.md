# M2.6: Region-only locations and the jobs.company_id foreign key

Base: commit `5a6e0dc` on branch `feat/m2-companies-ats`. Executed with the `execute-plan` skill.

## Goal
1. A location made only of region phrases ("LATAM", "Americas", "Global", "EMEA") no longer counts as an office job. Its workplace type is unknown, so the region rule decides.
2. `jobs.company_id`'s foreign key in `schema.ts` matches the real database, so drizzle's snapshot stops claiming `ON DELETE SET NULL`.

- Decisions already made:
  - **T1:** a location text is region-only when nothing but punctuation and spaces is left after removing every region phrase from `PHRASES` (case-insensitive, whole words). When **every** non-empty location text is region-only, `deriveWorkplaceType` returns `null` (unknown) instead of `"onsite"`. Country names don't count as region phrases, so a bare "Argentina" or "United States" stays `"onsite"`. That's the safe side: it may be an office. Remote, hybrid and onsite words still win, as today.
  - **T2:** the real DB has `jobs.company_id → companies(id)` with `ON DELETE NO ACTION`. drizzle-kit dropped the `onDelete` clause when it generated `ALTER TABLE ... ADD company_id` in `0001`, but `schema.ts` and the snapshots say `"set null"`. We never delete companies (they're set inactive), so we align `schema.ts` to the real DB by removing `{ onDelete: "set null" }`, and let `db:generate` produce the migration that brings the snapshot in line.

- `src/core/location-filter.ts`: `checkLocation` rejects only `"hybrid"` and `"onsite"`. Unknown workplace types pass, and then regions are checked against `ALLOWED_JOB_REGIONS`.

### T1: A region-only location is unknown, not an office
- Depends on: none
- Files: `src/core/locations.ts`, `src/core/locations.test.ts`, `src/sources/ats/greenhouse.test.ts`
- Behavior: in `deriveWorkplaceType`, after the three keyword checks and before the final fallback:
  ```
  nonEmpty = locationTexts.filter((t) => t.trim() !== "")
  if (nonEmpty.length === 0) return null                      // as today
  regionOnly = (t) => !/[\p{L}\p{N}]/u.test(consume(t, PHRASE_MATCHERS, new Set()))
  if (nonEmpty.every(regionOnly)) return null
  return "onsite"
  ```

## Gotchas
- T1: `PHRASE_MATCHERS` regexes have the `g` flag. `consume` uses `.replace`, which is safe with `g`. Don't call `.test` on those regexes directly, because `lastIndex` would carry over between calls.
- T1: pass a new `Set` to `consume` for each text. Don't reuse `deriveRegions`' set.
- T1: "Anywhere", "Worldwide" and "Global" are both region phrases and (except "Global") remote words. The remote check runs first, so `["Anywhere"]` stays `"remote"`, and only `["Global"]` becomes `null`.
- T2: drizzle's migrator runs migrations inside a transaction, where `PRAGMA foreign_keys=OFF` has no effect. That's why the copy check in step 4 is required before touching the real DB.
- T2: the copy step must include the WAL files (`jobs.db-wal`, `jobs.db-shm`), or the copy can miss recent writes. `cp data/jobs.db* data/m26-copy/` handles that. `data/` is gitignored, so the copy is never committed; delete `data/m26-copy/` after T2.
