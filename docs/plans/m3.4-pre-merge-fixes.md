## Key code
- `src/core/job-filter-rules.ts`:
  - `matchesKeywords(job: Pick<RuleInput, "title" | "departments" | "tags">, keywords: readonly string[]): boolean`. It normalizes `[title, ...departments, ...tags].join(" | ")` once, then tests each keyword with `new RegExp(\`(?<![a-z0-9])${escapeRegExp(normalize(k))}(?![a-z0-9])\`)`, which has **no flags**.
  - `mentions(text, phrase)` uses `new RegExp(\`(?<![\\p{L}\\p{N}])${escapeRegExp(normalize(phrase))}(?![\\p{L}\\p{N}])\`, "u")`. This is the target pattern.
  - `normalize` lowercases, turns `-`, `_` and `/` into spaces, collapses whitespace and trims. `escapeRegExp` escapes only regex syntax characters, so its output is valid with the `u` flag (`mentions` already relies on that).

## Gotchas
- **The `u` flag is required.** Without it, `\p{L}` means the letter `p` followed by `{L}`, and the regex silently matches the wrong thing.
- **Double the backslashes in the template literal** (`\\p{L}`), exactly as `mentions` does. A single `\p` in a template string becomes just `p`.
- **Don't change `normalize` or `escapeRegExp`.** `mentions` and the hyphen tests depend on them.
- **`CLAUDE.md` uses an en dash (`–`)** in these lines, not a hyphen. Copy the replacement lines exactly.
- `config/job-filter-rules.json` doesn't exist locally; the tests read the example file. Don't create the personal file.
