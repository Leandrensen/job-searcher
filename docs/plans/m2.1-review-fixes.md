## Gotchas
- `toEqual` treats a property set to `undefined` like a missing one, but `"httpStatus" in result` doesn't. That's why T3 says to leave the field out, not set it to `undefined`.
- In T2, `nullOn404` only catches `HttpError` 404s. `createFixtureHttp` throws `HttpError` for `{ status }` routes, so the test works through the real path.
- T5: the per-host override lookup must use the shared key, or a future `perHostMinIntervalMs["recruitee.com"]` would silently do nothing.
- T6 changes behavior for candidates that hit the resolve runner's rate-limit skip error ("... is rate limiting us, skipped for this run"). They now become `error` (retried tomorrow) instead of `ambiguous`. That's intended.
- T6 side effect: a probe that fails on every run keeps a candidate in `error` and retries it daily. That's accepted: it's one request per ATS per day.
- T8: `CandidateRow["status"]` widens. Check that the `company review` listing and `companyCounts` still compile and behave the same (they don't switch on candidate status).
- Run `nvm use` in each new shell. Node 20 segfaults with this toolchain.

## Open questions / assumptions
Decided by the spec author. Confirm before executing; stop and ask if the user disagrees.
1. **T3 adds an optional `httpStatus` to `FetchResult`.** This isn't the `SourceAdapter` interface `CLAUDE.md` protects, but it's in the same file.
2. **T4: a SmartRecruiters company with more than 5,000 postings is an error every run** (it stays active and no jobs are stored), rather than storing a partial list. Partial lists would wrongly close jobs.
3. **T9 drops EU links instead of supporting the EU APIs**, which would need an API region on `companies` (a schema change) and live verification of the EU endpoints.
4. **T8: a rejected candidate never comes back automatically**, not even with a new direct link. `company add <ats> <slug>` remains the way to add it by hand.
