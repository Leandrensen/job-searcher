# M3.2: Job filter rule fixes

Base: commit `8ec3526` on branch `feat/m3-ranking`. Executed with the `execute-plan` skill.

## Goal
Fix three problems in `config/job-filter-rules.json` handling before the M3 PR:
1. Exclusions treat hyphens, slashes and underscores like keywords do.
2. A rule entry made only of punctuation is rejected instead of matching every job.
3. The example rules stop excluding the Marketing department that their own keywords (`martech`, `marketing technology`) target.

- Decisions already made:
  - **Exclusions** (`excludeTitleKeywords` and `excludeDepartments`) use the **same normalization as keywords** on both sides (lowercase; `-`, `_` and `/` become spaces; whitespace collapsed), then a whole-word match. "Front-End Developer" is then excluded by `"front end"`, just as it's matched by the keyword `"front end"`.
  - **Every entry** of `keywords`, `excludeTitleKeywords` and `excludeDepartments` must contain at least one letter or digit. Otherwise it normalizes to an empty pattern, which matches everything.
  - **The example drops `"Marketing"`** from `excludeDepartments` and keeps the `martech` keywords. The keyword list stays identical to the old built-in list, so board discovery is unchanged.

## Key code
- `src/core/job-filter-rules.ts`:
  - `JobFilterRulesSchema` (strict; `nonEmptyStrings = z.array(z.string().trim().min(1))` for `keywords`, `excludeDepartments` and `excludeTitleKeywords`).
  - `normalize(s)` (lowercase, `[-_/]` to space, collapse, trim) and `escapeRegExp`.
  - `mentions(text, phrase)`: a whole-word, case-insensitive match **without** normalization, used by the title and department exclusions.

## Tasks

### T1: Exclusions normalize like keywords
- Depends on: none
- Files: `src/core/job-filter-rules.ts`, `src/core/job-filter-rules.test.ts`
- Behavior: replace `mentions(text, phrase)` with a normalized whole-word match:
  ```
  mentions(text, phrase) = new RegExp(`(?<![\p{L}\p{N}])${escapeRegExp(normalize(phrase))}(?![\p{L}\p{N}])`, "u").test(normalize(text))
  ```
  `normalize` already lowercases, so the `"i"` flag is no longer needed. Title and department exclusions keep their order and reasons.
- Failure cases: an exclusion phrase that normalizes to `""` can't reach this function after T2. Don't add a runtime guard here.
- Tests first (add rows to the `checkJobRules` `it.each` table; `keywords: ["react"]` in each rule set unless stated):
  - `["a hyphenated title is excluded by a spaced phrase", { title: "Senior React Front-End Developer" }, { keywords: ["react"], excludeTitleKeywords: ["front end"] }, { pass: false, reason: "title" }]`
  - `["a spaced title is excluded by a hyphenated phrase", { title: "Senior React Data Scientist" }, { keywords: ["react"], excludeTitleKeywords: ["Data-Scientist"] }, { pass: false, reason: "title" }]`
  - `["an underscored department is excluded", { departments: ["Customer_Success"] }, { keywords: ["react"], excludeDepartments: ["Customer Success"] }, { pass: false, reason: "department" }]`
  - `["an exclusion inside another word doesn't match", { title: "Senior Reactive React Developer" }, { keywords: ["react"], excludeTitleKeywords: ["React Dev"] }, { pass: true }]`. Normalized, "react dev" isn't followed by a word boundary in "react developer", so it passes.
  - All existing rows stay unchanged and pass.
- Verify: `npm test -- src/core/job-filter-rules.test.ts` passes.
- Commit: `fix(m3): exclusions normalize hyphens and slashes like keywords (M3.2 T1)`

### T2: Reject rule entries without a letter or digit
- Depends on: T1
- Files: `src/core/job-filter-rules.ts`, `src/core/job-filter-rules-file.test.ts`
- Interfaces: change `nonEmptyStrings` to
  ```ts
  z.array(z.string().trim().regex(/[\p{L}\p{N}]/u, "must contain a letter or digit"))
  ```
  This covers `keywords` (still `.min(1)` on the array), `excludeDepartments` and `excludeTitleKeywords`. An empty string also fails the regex, so `min(1)` on the string is no longer needed.

  - `{"keywords":["react"],"excludeDepartments":[" "]}` → `"config/job-filter-rules.json: excludeDepartments.0: must contain a letter or digit"`
  - `{"keywords":["C++"]}` and `{"keywords":["node.js"]}` stay valid.

## Gotchas
- T1: normalize **both** the text and the phrase. Normalizing only one side breaks the match ("front end" vs "front-end").
- T1: the boundary classes are `\p{L}\p{N}` with the `"u"` flag, which differs from the keyword matcher's `[a-z0-9]`. Keep the exclusions Unicode-aware, as before; only the normalization changes.
- T2: the regex runs on the trimmed string, so `" "` fails as intended. Don't drop `.trim()`.
- The last real fetch used the example rules with `Marketing` excluded, so a few martech jobs may have been closed. The next daily fetch (or `npm run fetch -- --force`) reopens any that now pass. Don't change data by hand.
