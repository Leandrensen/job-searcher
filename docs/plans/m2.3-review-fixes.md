# M2.3: Fixes from the third M2 code review

Base: commit `e36325e` on branch `feat/m2-companies-ats`. Executed with the `execute-plan` skill.

## Goal
Fix four problems before the M2 PR is opened:
1. Failed companies are fetched on every run instead of about once a day.
2. A website domain matches inside longer domains.
3. ATS links found in board postings confirm a company without proof.
4. A candidate whose probe always fails is retried every day forever.

## Key code
- `src/db/schema.ts`: `companies.lastFetchedAt` (`text("last_fetched_at")`, comment "Last successful fetch."), `companies.consecutiveFailures` (404s only), `companyCandidates` (`attempts`, `lastCheckedAt`, `nextCheckAt`, `status` enum including `"error"` and `"rejected"`).
- `src/db/companies.ts`:
  - `recordCompanyFetch(db, companyId, outcome, nowIso)`. Outcomes are `{ kind: "success" }` (sets `consecutiveFailures: 0, lastFetchedAt, lastError: null`), `{ kind: "not_found", error }` (increments `consecutiveFailures`, sets `lastError`, deactivates at 3) and `{ kind: "error", error }` (sets only `lastError`).
  - `listDueCompanies(db, ats, nowIso, { force?, minHours? })`: active companies with `lastFetchedAt` null or at least `minHours` (default 20) ago.
  - `recordResolution(db, candidateId, result, nowIso)`: in the `"error"` case it sets `status: "error"`, `nextCheckAt: addDays(nowIso, 1)`, and `attempts + 1`. The `confirmed`, `ambiguous` and `not_found` cases also bump `attempts`. `addDays` is a local helper.
- `src/sources/ats-runner.ts`: `runAtsSources`. It calls `recordCompanyFetch` with `not_found` (`result.httpStatus === 404`), `error` (any other failed fetch, and in the `catch` for DB or unexpected errors) or `success`. On `httpStatus === 429` it records nothing and stops that ATS.
- `src/companies/resolve.ts`:
  - `proveIdentity(candidate, ats, probe)`. Rule 2 uses `websiteDomain(candidate.website)`, then `probe.urls` host equality or a subdomain check, or `probe.texts.some((t) => t.toLowerCase().includes(domain))`. `escapeRegExp` is a local helper.
  - `resolveCandidate`. Step 1: `direct = extractAtsRefs([careersUrl, website, ...atsHints].filter(Boolean).join(" "))`; each ref is probed, and one that exists (SmartRecruiters needs `postingCount > 0`) is confirmed with no identity check. Step 2 probes guessed slugs. `probed` is a set of `"<ats>/<slug>"`, and `unproven` is an array of `AtsRef`. The final order is confirmed → error → ambiguous → not_found.
- `src/companies/slugs.ts`: `websiteDomain(url)` (lowercase host without `www.`), `extractAtsRefs(text)` and `AtsRef`.
- `src/companies/discover.ts`: `recordCandidatesFromBoardJobs` stores ATS links found in board postings as `atsHints`.
- `src/companies/resolve-runner.ts`: when a probe gets a 429, the rate-limit breaker makes later probes of that ATS throw `"<ats> is rate limiting us, skipped for this run"`. Those resolutions are `error`s.
- Test helpers:
  - `src/db/companies.test.ts`: `T0`, `plusDays`, `plusHours`, `add(slug, ats?)` inside `describe("companies")`, `candidates()`, `allCompanies()`.
  - `src/sources/ats-runner.test.ts`: `fakeAts`, `addCompany`, `run(adapters, { force?, at?, log? })`, `company(slug)`, `GOOD`, `T0`, `hoursLater(h)`.
  - `src/companies/resolve.test.ts`: URL helpers `gh`, `ghJobs`, `lever`, `ashby`, `recruitee`, `sr`, plus `candidate(over)`, `resolve(candidate, routes)` (returns `{ resolution, calls }`), and `probe(over)` inside `describe("proveIdentity")`.
  - Fixtures: `test/fixtures/resolve/lever-globex-two.json` (2 Lever postings that mention "Globex") and `lever-globex-one-unrelated.json` (1 posting with no name).
