# M3.5: Fixes before M4 scoring

Base: commit `ae67559` on branch `feat/m3-ranking`. Executed with the `execute-plan` skill.

## Goal
Before Claude scoring (M4) starts paying per job:
1. Each posting is ranked once. A posting listed by one company in several cities, a duplicate and its original, and a copy from a third job site all count as one job.
2. `npm run rank` re-checks open jobs against the current job filter rules and skips the ones that fail.
3. "Semi Senior" titles are classified as `mid`.
4. SmartRecruiters postings dropped before their detail request are counted in `filteredRules` / `filteredLocation`. The comment that says salary rules apply to SmartRecruiters is corrected.

- Decisions already made (the owner approved both decisions that needed approval):
  - **One posting, one ranked job (owner's decision).** Open jobs are the same posting if any of these hold:
    - one is a `duplicateOf` the other;
    - they share `dedupeKey` (normalized company + normalized title, so cities don't matter);
    - they share a non-null `applyUrl`.

    Ranking keeps the lowest id among them. Grouping happens when ranking reads the jobs, so it covers rows already stored and copies that arrive after an original closes. `findOriginal` / `upsertJobs` stay unchanged.
  - **Rank re-checks the rules but changes nothing.** Jobs that fail the current `config/job-filter-rules.json` are skipped by rank: not embedded, not ranked. They stay open until the next fetch closes them, because the ATS runner closes a company's jobs that no longer pass.
  - **"Semi senior" is `mid`.** That includes ranges such as "Junior/Semi-Senior". A plain "Semi" stays `mid`, as it is today.
  - **`FetchContext.onPrefiltered` (owner approved this interface change).** An optional callback `(reason: "rules" | "location") => void`.
    - SmartRecruiters calls it for each posting it drops before the detail request.
    - The ATS runner counts those calls into `filteredRules` / `filteredLocation`, and also into `fetched`, so the summary reads consistently: fetched = stored + filtered + invalid.
  - **SmartRecruiters has no salary.** The public API's list and detail responses carry no salary, so salary rules never apply there (unknown values pass). Only the comment changes.
