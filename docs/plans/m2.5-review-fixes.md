# M2.5: Keep closed jobs' identity, and small follow-ups from the fifth M2 review

Base: commit `68c4463` on branch `feat/m2-companies-ats`. Executed with the `execute-plan` skill.

## Goal
1. Closed jobs are never deleted. After 30 days only their descriptions are dropped, so a posting that comes back reuses its row (and, from M3/M4, its embedding and score), which keeps "embedded once, scored once, ever".
2. Companies based outside the allowed countries aren't fetched.
3. A newly learned careers URL reopens an unresolved candidate.
4. Resolution timestamps are taken when each result is recorded.

- Decisions already made:
  - **T1–T2:** replace `purgeClosedJobs` (hard delete) with `compactClosedJobs`. For jobs closed at least 30 days ago it sets `descriptionHtml` and `descriptionText` to `""` and keeps the row. A row whose descriptions are already both `""` doesn't count, so the number reported is "rows changed this run". The fetch CLI line becomes `Compacted <n> closed jobs`. This supersedes the 2026-11-16 decision "Closed jobs are deleted 30 days after closing".
  - **T3:** the ATS runner skips companies whose home country isn't allowed (`isAllowedHomeCountry`), before any request. Every job from such a company would be dropped by the location filter anyway. An unknown (null) home country is still fetched.
  - **T4:** a newly filled `careersUrl` reopens a `not_found`, `error` or `ambiguous` candidate, like a new ATS hint does. A newly filled `website` still doesn't (unchanged, and covered by an existing test).
  - **T5:** `resolveDueCandidates` reads the due list at the start time, but records each result with `opts.now()` taken when that result is recorded.

### T1: `compactClosedJobs` keeps the row and drops only the descriptions
- Depends on: none
- Files: `src/db/queries.ts`, `src/db/queries.test.ts`
- Interfaces:
  ```ts
  /** Drops the descriptions of jobs closed at least `days` (default 30) days ago, keeping the row. Returns how many rows changed. */
  export function compactClosedJobs(db: Db, nowIso: string, days = 30): number;
  ```
- Behavior: a single `UPDATE jobs SET description_html = '', description_text = ''` where `closedAt IS NOT NULL AND closedAt <= cutoff AND (descriptionHtml != '' OR descriptionText != '')`, returning `.run().changes`. It doesn't touch `duplicateOf` or any other column. Leave `purgeClosedJobs` in place for now (T2 removes it).
- Failure cases: no closed jobs → `0`. A second run over the same rows → `0`. Open jobs and jobs closed less than `days` ago are untouched.
- Tests first (`queries.test.ts`, next to the purge tests):
  - `compaction drops descriptions of jobs closed 30+ days ago and keeps the rows`: create `ats("old")`, `ats("recent")` and `ats("open")` for company `acme`, then close `old` at `daysAgo(31)` and `recent` at `daysAgo(29)` (same calls as the purge test). `compactClosedJobs(db, NOW)` returns `1`. `rows().map((r) => [r.externalId, r.descriptionHtml, r.descriptionText])` equals `[["acme:old", "", ""], ["acme:recent", "<p>x</p>", "x"], ["acme:open", "<p>x</p>", "x"]]`. A second `compactClosedJobs(db, NOW)` returns `0`.
  - `a compacted job that reappears keeps its id and gets its description back`: compact `old` as above, note its `id`, then `upsertJobs(db, [ats("old")], NOW, { companyId: acme })`. The returned counts equal `{ inserted: 0, updated: 1 }`, and the row with `externalId "acme:old"` matches `{ id: <same id>, closedAt: null, descriptionHtml: "<p>x</p>", descriptionText: "x" }`.
  - `compaction keeps duplicate links`: set up a Lever duplicate of a closed Greenhouse job (as in `purge clears duplicate_of pointers first`), close the original at `daysAgo(40)`, and compact. Both rows still exist, and the Lever row's `duplicateOf` equals the original's id.
- Verify: `npm test -- src/db/queries.test.ts` passes.
- Commit: `feat(m2): add compactClosedJobs, which keeps closed jobs and drops their descriptions (M2.5 T1)`
- [x] Done
